# Service Planner Agent for Claude Code

サービス企画を**対話形式で深堀り**しつつ、**デビルズ・アドボケイト**で論理破綻や甘さを容赦なく指摘し、最終的に `output/draft.md` (添付テンプレート形式) に出力するエージェントシステムです。

各フェーズ完了時に**中間アウトプットを自動保存**するため、セッションが切れても**続きから再開**できます。トークン消費を最小化するため、Claude Code のサブエージェント分離・モデルルーティング・プランモードを組み合わせています。

---

## 構成

```
service-planner/
├── CLAUDE.md                              # プロジェクト指示（毎セッション読み込まれるので最小限）
├── .claude/
│   ├── settings.json                      # トークン節約用の環境変数
│   ├── agents/
│   │   ├── devils-advocate.md             # ⚡ 批判担当（Sonnet）
│   │   ├── user-researcher.md             # WHY深堀り担当（Sonnet）
│   │   ├── competitor-researcher.md       # 競合調査担当（Haiku）
│   │   └── template-writer.md             # 整形・進捗管理担当（Haiku、3モード）
│   ├── commands/
│   │   ├── plan-service.md                # メイン: /plan-service
│   │   ├── plan-status.md                 # 進捗確認: /plan-status
│   │   └── devils-check.md                # 単発批判: /devils-check
│   └── templates/
│       └── draft-template.md              # 出力テンプレート
└── output/                                # ここに draft.md が生成される（フェーズごとに自動更新）
```

## セットアップ

### 1. Claude Code をインストール

```bash
npm install -g @anthropic-ai/claude-code
```

### 2. このプロジェクトを置く

任意のディレクトリ（例 `~/projects/service-planner/`）にこの一式を配置。

### 3. Claude Code を起動

```bash
cd ~/projects/service-planner
claude
```

### 4. 確認

```
> /agents
```

`devils-advocate` `user-researcher` `competitor-researcher` `template-writer` の4つが表示されればOK。

```
> /
```

`/plan-service` `/plan-status` `/devils-check` がリストにあればOK。

## 使い方

### 新規でメインフローを始める

```
> /plan-service
```

または企画タネを引数で渡す:

```
> /plan-service クラブハウスでの違和感から始まった音声SNSの企画
```

エージェントが4フェーズで質問してきます:

1. **体験と真因の発掘** — WHY深堀り → デビルズ・アドボケイト① → 💾 章2・章3 を保存
2. **ユーザーと競合** — 競合調査 → デビルズ・アドボケイト② → 💾 章4・章5 を保存
3. **価値とMVP** — 機能整理 → デビルズ・アドボケイト③ → 💾 章6〜章8 を保存
4. **展開・技術・最終仕上げ** — 💾 章9・章10、最後に章1（概要）を保存

各フェーズ完了時に `output/draft.md` が更新され、`/compact` を促されます。

### 途中で中断したあと再開する

セッションが切れた、`/clear` した、別の日に続きをやりたい — どの場合でも:

```
> /plan-service
```

エージェントが**自動でレジュームチェック**を実行し、こう言ってきます:

```
🔁 前回の進捗が見つかりました:
  - フェーズ2まで完了
  - 真因: 「初対面の場で承認を失う恐怖」
  - ユーザー: 「20代後半〜30代の社会人で勉強会に参加し始めた人」
  - 最終更新: 2026-05-06T10:23:00

次のいずれかを選んでください:
  ① 続きから再開する（フェーズ3から）
  ② 前のフェーズの内容を見直したい（章番号を指定）
  ③ 最初からやり直す（output/draft.md を削除して新規開始）
```

「①」と答えれば**完了済みフェーズの本文は再読み込みせず**、フロントマターの要約だけを参照して即座にフェーズ3から始まります。

### 進捗だけ確認したい

```
> /plan-status
```

ファイル本文は読まないため、トークン消費はほぼゼロ。長い対話の途中で「いま何フェーズ目だっけ?」を確認するのに最適。

### 単発で批判だけ受けたい

```
> /devils-check ターゲットユーザーの実在性を疑ってほしい
```

## 中間アウトプットの仕組み（レジューム機能）

### `output/draft.md` の構造

ファイル冒頭に YAML フロントマターで進捗ステータスを保存:

```yaml
---
service_planner_status:
  last_completed_phase: 2
  phase1_truth: "初対面の場で承認を失う恐怖"
  phase2_user: "20代後半〜30代の社会人で勉強会に参加し始めた人"
  phase3_value: ""
  last_updated: "2026-05-06T10:23:00"
---

## 1. サービス概要
（未記入）

## 2. このアイデアはどこから生まれたか
...（フェーズ1で保存された内容）

## 3. 課題の整理
...（フェーズ1で保存された内容）

## 4. 想定ユーザーについて
...（フェーズ2で保存された内容）

...
```

### なぜフロントマターに要約を入れているか

レジューム時に**完了済みフェーズの本文を Read しないで済む**ため。フロントマターの先頭30行だけ読めば、エージェントは「真因は何か」「ユーザーは誰か」を把握でき、即座に次フェーズに進めます。

これは長い `draft.md` を毎回コンテキストに載せる愚行を回避する設計です。

### 上書きルール

- フェーズ1完了時: 章2、章3 のみ Edit で更新
- フェーズ2完了時: 章4、章5 のみ Edit で更新
- ...
- 一度書いた章を後続フェーズで触らない（差分編集に徹する）

## トークン節約の仕組み

このエージェントはClaude Codeの公式ベストプラクティスを適用しています。

### 1. CLAUDE.md は最小限

CLAUDE.md は**毎セッション全文ロード**されるため、肥大化させない。判断ロジックはサブエージェントの定義側に置き、必要なときだけロードされる構造にしています。

### 2. サブエージェントを Haiku で動かす

`.claude/settings.json` で:

```json
{
  "env": {
    "CLAUDE_CODE_SUBAGENT_MODEL": "haiku"
  }
}
```

整形・調査タスクは Haiku で十分、かつ Sonnet の **約 1/4 のコスト**。批判のように深い推論が必要なものだけサブエージェント側で `model: sonnet` を明示指定。

### 3. サブエージェントは独立コンテキスト

メインの会話履歴を継承しません。狭く明確な briefing で起動し、**要約だけ**メインに返却。
- `devils-advocate` → 400字以内のレポートのみ返す
- `user-researcher` → 500字以内
- `competitor-researcher` → 400字以内
- `template-writer` → 80字以内の完了報告のみ

### 4. プランモードで先に同意を取る

各フェーズを実行する前にユーザーが Plan を見て修正できるため、**やり直しによるトークン浪費が起きない**。

### 5. `/compact` を強制的に促す

4フェーズすべての完了時にコンパクト実行を案内。会話履歴が要約版に置き換わるためコンテキスト窓に余裕が生まれます。

### 6. `MAX_THINKING_TOKENS=8000`

extended thinking のデフォルトは数万トークンに達することがあり、企画相談には過剰。8000 に絞っています。

### 7. 思考プロセスは返却しない

サブエージェントは**結論だけ**メインに返す規約。「なぜそう判断したか」をメインの履歴に積まないので、後続ターンでの再処理コストが下がります。

### 8. レジューム時に本文を再読み込みしない

フロントマターの要約だけで十分次フェーズに進めるため、**完了済みフェーズの章本文をコンテキストに載せない**。長期プロジェクトで威力を発揮します。

## ターミナルからのトークン節約系プラグイン

Claude Code v2 以降は `/plugin` コマンドでマーケットプレイスが使えます。本エージェントと併用すると効果的なものを紹介します。

### 公式 Anthropic マーケットプレイス

```
> /plugin marketplace add anthropics/skills
> /plugin install document-skills@anthropic-agent-skills
```

document-skills には pdf / docx / xlsx / pptx の整形スキルがあり、企画書を docx 化したい場合に活用できます。

### everything-claude-code

トークン最適化系のスキル群。**`strategic-compact`** スキルが特に有用で、自動コンパクトに頼らず**論理的な区切りで `/compact` を提案**してくれます。

```
> /plugin marketplace add affaan-m/everything-claude-code
```

### pensyve（メモリプラグイン）

セッション間で「決定済みの真因」「過去のデビルズ・アドボケイトの指摘」を保持するメモリ機能。**本エージェントの中間アウトプットと組み合わせると、より長期の企画温めに強くなります。**

```
> /plugin marketplace add major7apps/pensyve
> /plugin install pensyve@major7apps-pensyve
```

### マーケットプレイスを探す

```
> /plugin
```

または以下のディレクトリで検索:
- https://claudemarketplaces.com/

## ターミナルでの追加トークン節約Tips

### 単発実行（セッション肥大を避ける）

```bash
claude -p "/plan-status"
```

`-p` フラグで非対話モード。1ターンで終わるためコンテキストが残らない。**進捗確認だけしたいときに最適**。

### モデル指定の単発呼び出し

```bash
claude --model claude-haiku-4-5 -p "draft.md の章立てだけ確認して"
```

軽い確認は Haiku で。

### パイプで必要な部分だけ渡す

```bash
head -n 30 output/draft.md | claude -p "進捗ステータスを教えて"
```

ファイル全体を Read させるとトークンを食うので、フロントマターだけパイプで渡すのが効きます（自動レジューム機能と同じことを手動でやる版）。

### ステータスラインでコスト可視化

```
> /cost
```

または `~/.claude/settings.json` に statusline を設定し、消費トークンを常時表示。

### 不要セッションは `/clear`

別のテーマに移るときは `/compact` ではなく `/clear`。前の文脈はリセットされます。**本エージェントは中間アウトプットがディスクに残るので、`/clear` しても進捗は失われません。**

## 推奨される使い方パターン

### 短時間集中（1〜2時間で完走）

各フェーズ完了 → `/compact` → 次フェーズ。最後にまとめて `output/draft.md` を確認。

### 数日に分けて温める

- 1日目: フェーズ1だけ実施 → セッション終了
- 2日目: `/plan-status` で確認 → `/plan-service` で続きから
- 3日目: 同上...

途中で寝かせて思考を熟成させたい人に向いています。

### 並行して複数企画

`output/` の代わりに `output-projectA/` `output-projectB/` のようにディレクトリを切り替えれば複数企画を並行管理可能（手動で `output/draft.md` をリネームしてください）。

## カスタマイズのヒント

### デビルズ・アドボケイトをもっとキツくしたい

`.claude/agents/devils-advocate.md` の「禁止事項」に追加:

```
- 1つでも論理破綻があれば、企画全体を「現時点では成立しない」と宣告する
```

### テンプレートの章を増やす

`.claude/templates/draft-template.md` に章を追加するだけ。`template-writer` は構造を機械的に踏襲するので追従します。

ただしフェーズと章番号の対応を変える場合は、`plan-service.md` と `CLAUDE.md` の「フェーズと出力セクションの対応」表も合わせて更新してください。

### 別ジャンル（toB提案書など）に転用

`plan-service.md` のフェーズ構成を書き換えるだけで、面接準備・論文構造化・キャリア相談など別用途にも転用可能です。レジューム機構（フロントマター + 章単位の差分書き込み）はそのまま流用できます。
